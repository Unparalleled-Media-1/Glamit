# Feature freeze, launch gaps and acceptance contracts

5 November 2026, Africa/Johannesburg. Governing source: [Final Feature Freeze & Gap Closure](sources/2026-11-final-feature-freeze.txt). This is a bounded gap/contract specification, not a claim that the platform is launch-ready. No backend/database/auth/payment system is replaced in the visual recovery. Canonical migrations remain the only schema history. Existing API/OpenAPI describe implemented endpoints; **proposed contracts below are not live endpoints**.

The source says: **“Do not introduce new major modules without explicit approval after feature freeze.”** The separate [visual recovery](sources/2026-11-mandatory-visual-quality-recovery.txt) says: **“Submit the five golden screens for visual approval before redesigning the remaining screens.”** Current work stops at those design patterns and specifications. Destination/weather is a separately documented candidate, not a silently added launch module.

## Shared contract and permission requirements

One canonical `app_user` identity; existing organization/member/workspace capability grants remain authoritative. Owner access is checked on every personal resource, and current membership/capability/staff authority on every tenant operation including idempotent replay. Unknown age/market capabilities fail closed. No client selector, uploaded JSON, checkbox, source URL or model assertion can grant a role, stock evidence, valid consent or trusted payment status.

All future mutating contracts use typed bounded bodies, stable idempotency keys, revision/ETag preconditions, UTC server timestamps, currency + integer minor units, source/version/expiry evidence, transaction-scoped audit and outbox/inbox dedupe. Return explicit `unavailable`, `denied`, `stale`, `needs_confirmation`, `no_match` or `unknown_cost`; never silently invent success. Private photos/reports/preferences and sensitive cultural/religious context stay outside advertiser/event analytics contracts.

## Cross-cutting release tests

- **R01:** execute Understand me → Style me → Show me → verified local offer/quote → accepted full obligations → actual payment/order/fulfillment → commission/settlement → partial/full return, with actual qualified integrations. Fixture success alone is insufficient.
- **R02:** replay/duplicate/out-of-order source, job, listing, order, payment, fulfillment and refund events; crash between external side effect and local commit. No duplicated credit/commission/payout, stale publication or missing compensation.
- **R03:** user/tenant/staff cross-resource access, suspended membership, revoked capability, expired grant, stale idempotency replay, privacy withdrawal and direct-client RLS remain denied.
- **R04:** inspect all advertiser/analytics payloads: no photos, inferred traits, private reports, coverage/religious context, precise location or individual wardrobe/conversation contents.
- **R05:** diverse cohort/provider benchmarks, human task usability, screen-reader/device safe areas/keyboard, offline/retry/cancel, localization and recoverability must be measured. Unit/build/screenshot success is not launch approval.

## Deferred contracts retained without new module activation

Phase 2 creator attribution requires signed, consented source lineage and deduped order/line attribution with refund reversals; the platform 10% is earned once and creator remuneration is a separate approved obligation. Price/restock/follow-up alerts require explicit owner opt-in, real current evidence and revocation, never fabricated notifications. Tailor/rental/group flows need scoped reference sharing, feasibility, full quote terms, fitting/deadline/resource holds and actual privacy policy before booking or production claims. Destination/weather has its own proposed contracts and evidence gates. Nothing in this document enables provider spend or replaces working canonical services.
