## Delivered candidate behavior

- Sixth Personalized Results route: original/reference provenance, unsupported and tentative findings, provider/model/time, explicit processing permission, independent user corrections, concepts and Studio handoff. No model estimates exist in the default build. Notes remain separate from original findings and are never persistent profile data.
- Authenticated application composition can supply the typed `CompanionConnection`. The preview/default app registers none. Owner/photo binding, full finding sets, uncertainty, correction/direction revisions, approved media origins, expiry, cancellation and stale-response rejection are checked. This interface is not an implemented authenticated upload or analysis endpoint.
- A chosen analysis direction enters the appropriate Studio tool. The explicit generation request includes user corrections. A valid actual preview unlocks a separate original/preview comparator on web or original/generated toggle in native. Unavailable services do not change the original or fabricate a preview.
- Destination planning lives under Personal Stylist with Event Stylist and Results links. Dates, country, activities, comfort preferences, sourcing and user-authored packing entries work in session. Editing a trip preserves packed items and invalidates previous weather. Qualified weather responses must match dates/location/timezone, distinguish forecast/seasonal/unavailable and expire. No historical fallback or weather-based AI outfit is invented.
- Explicit category/tags/country/city requests can reach a supplied catalog adapter. Organic and Sponsored remain separately labeled. Matching receives no photo, findings or private corrections. Provider place-search candidates never become verified GLAM merchants automatically. Services lead to the existing feasibility-request planning flow; no slot or quote is fabricated.
- Verified variant detail reuses the approved light detail structure and never substitutes editorial imagery for a missing qualified product image. Verified variant review, session cart, server quote, hosted checkout handoff and order-status views have typed orchestration. Editorial studies remain non-purchasable. No client total, commission, payout, settlement or financial ledger is introduced. A `paid` receipt must come from the owner-bound order adapter. Pending/failed/cancelled responses never produce a paid confirmation. Quotes are invalidated by cart/location/identity changes; expired quotes cannot launch checkout. Pending order lookup is independent of checkout quote freshness.
- Private analysis, previews, corrections, carts/receipts and trip notes are not written to durable profile storage. Clearing/replacing a photo invalidates analysis and preview; changing identity invalidates private state. Quote requests allowlist country/city/currency rather than serializing the full companion profile.

## Approved integration stack

OpenAI analysis/Advisor; Replicate qualified hair/makeup workflows; FASHN apparel try-on; Supabase Auth/PostgreSQL/Storage only after G0; GLAM-owned marketplace/matching/orders/commission ledger and booking engine; Stripe Connect where eligible; Peach for approved South African capabilities; Google Maps; Open-Meteo; Resend; Twilio; Sentry; optional professional Google Calendar sync later.

Server preparations are under `services/api/src/glam_api/integrations`. Typed OpenAI structured analysis/Advisor, FASHN run/status, Replicate pinned predictions/status, Google Places discovery and entitlement-gated Open-Meteo request adapters use injectable transports. Resend/Twilio have read-only health preparations. Configuration comes only from process secret bindings, never a frontend `.env` or a committed key. See `deploy/integrations/.env.example` for names, with all sensitive services server-only. No environment configuration was changed.

No new privileged route is mounted and no provider is wired to the public/default app. Before registering adapters: authenticate through existing identity; verify consent/policy/age/market; qualify model, storage rights, retention/deletion, commercial entitlement and spend; normalize provider responses into owner-bound application contracts. Browser `blob:` URLs cannot be passed to a remote image API as if they were uploaded images. Private media upload/server orchestration remain an explicit missing layer.

Reads retry at most three times for transient transport/429/5xx failures. Billable POSTs do not automatically retry; durable job IDs/reconciliation and provider-specific idempotency must be qualified before activation. Requests have timeouts and bounded JSON responses. Redirects cannot forward credentials. Failures expose stable codes, not remote response bodies, secret values, signed URLs or photos. OpenAI uses `store:false`; that is not a claim of zero vendor retention, contractual deletion or privacy qualification.

`NOT CONFIGURED` is the default without credentials/configuration. A configured key never proves connection. Supported read-only authenticated probes may yield `CONNECTED`; unsuccessful probes yield `DEGRADED`. A health check does not qualify model fidelity, commercial permission or end-to-end service operation. Public weather reachability is explicitly not called authenticated commercial readiness. A Sentry DSN alone is not an account-health credential. Supabase, payments, booking schemas and optional calendar remain gated rather than initialized.

## Acceptance boundary

The required live journey is **not accepted or operational**: upload → actual personal analysis → look exploration → real try-on → verified local product → cart → payment → webhook-backed order confirmation. Isolated test doubles prove only contracts and UI behavior. Credentials, qualified models/media, G0/identity/storage, source-backed supply, legal entity/country/settlement/refund validation, actual booking availability, authenticated probes and physical native recordings remain blocked.

The [regression report](../ux-regression-report.md) is supplied before any final approval request. No final product approval is requested while the live acceptance chain is blocked. Production data, existing financial/authentication code and canonical migrations remain unchanged.
