I agree with the direction you're pushing for: GLAM Beauty must feel and function like a premium, purpose-built iOS and Android application—not a website squeezed into a phone screen.

But there is an important technical distinction. React Native is capable of producing fully native applications. The problem may not be the programming language; it may be that Codex has reproduced the website's layout, navigation and interaction patterns inside React Native.

Flutter is a valid alternative, and I would authorize a controlled Flutter migration if the existing implementation cannot meet the native experience requirements. I would not authorize an immediate wholesale rewrite without first establishing what is wrong with the current UI.

## React Native versus Flutter

| Requirement                             | React Native / Expo | Flutter |
| --------------------------------------- | ------------------- | ------- |
| Genuine installed iOS/Android apps      | Yes                 | Yes     |
| Native camera and photo access          | Yes                 | Yes     |
| Biometric authentication                | Yes                 | Yes     |
| Native-feeling navigation               | Yes                 | Yes     |
| Smooth animations and gestures          | Yes                 | Yes     |
| Custom beauty and AI Studio interfaces  | Yes                 | Yes     |
| Reuse existing GLAM mobile source       | High                | Low     |
| Reuse existing FastAPI/Supabase backend | Yes                 | Yes     |
| Rewrite risk                            | Lower               | Higher  |

Flutter would give you excellent control over custom mobile UI rendering and animation. However, switching frameworks alone will not fix disconnected backend operations, incomplete user journeys or poor UX decisions.

My recommendation is a short, strict native-experience acceptance gate. If the current React Native implementation cannot satisfy it, move to Flutter without further rounds of cosmetic repairs.
