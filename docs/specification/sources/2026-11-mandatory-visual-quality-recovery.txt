Keep the five primary mobile destinations, but make the experiences much more visual.

## Five experiences that must be redesigned

Home — A personal beauty magazine

A premium editorial hero, personalized suggestions, trending looks, event inspiration, saved routines and localized recommendations. Large visual collections rather than grids of generic feature cards.

Analyze — A beauty consultation

Full-screen camera, lighting guidance, facial landmark visualization, clear progress feedback and beautifully illustrated results. Avoid unsupported numerical skin-health or beauty scores.

AI Studio — The signature experience

Full-screen portrait, swipeable hairstyles and makeup swatches, before/after slider, undo/reset, save, share and a persistent Get This Look action.

Shop — A curated beauty marketplace

Premium editorial collections, product close-ups, shade variants, verified sellers, local availability, sponsored placements and direct purchase. Location must be user-controllable.

Profile — My Style Passport

Saved analyses, looks, wardrobe, events, purchases, preferences, privacy controls and subscription details.

# 4. What I would change about the visual design

Suggested GLAM AI palette: warm ivory, powder blush, dusty rose, mauve, charcoal and champagne.

Use this palette as a foundation, not as a reason to make every screen pink.

The visual system should use large editorial photography, expressive but readable typography, premium product imagery, generous whitespace, carefully restrained glass effects, subtle motion and dark camera overlays where appropriate.

Importantly, AI Studio should have a different visual treatment from Shop. The Studio should prioritize the user's portrait; Shop should prioritize the products.

A face-analysis result should feel like a personalized beauty report. A product detail page should feel like luxury retail. A styling event planner should feel like a fashion editorial.

One generic card component cannot deliver all three.

# 5. The real reason Codex may be struggling

Codex is capable of implementing a high-quality interface, but an instruction such as "make the app look like these references" is not a sufficiently precise design specification.

It may independently choose layouts, spacing, images, navigation and components, producing technically valid screens that are visually inconsistent.

The fix is to change the workflow:

1. Define the design system: Typography, spacing, colors, buttons, navigation, imagery, cards, motion and responsive rules.

2. Design five representative screens first: Home, Face Analysis, AI Studio, Shop and Product Detail.

3. Review visual screenshots before connecting business logic: Compare the screens with the references at matching viewport sizes.

4. Approve the screen patterns: Lock the reusable components and interaction rules.

5. Implement functionality: Connect real AI, merchant data, checkout, advertisements and subscriptions.

6. Run visual regression tests: Prevent later code changes from degrading approved designs.

This approach also avoids the recurring problem of fixing one area while breaking another.

# 6. The instruction I would give Codex now

GLAM AI — Mandatory UX/UI Redesign and Visual Quality Recovery

# GLAM AI — Mandatory UX/UI Redesign and Visual Quality Recovery

## Objective

The existing GLAM AI interface is not meeting the visual or interaction standard required for a competitive, premium AI beauty application.

Treat the supplied reference images as the approved quality benchmark for visual sophistication, photographic emphasis, immersive AI interaction and premium commerce presentation.

Do not clone any competitor's branding, proprietary artwork or exact interface. Develop a distinctive GLAM AI design system that achieves comparable production quality.

## Critical directive

STOP expanding the feature set.

Do not rewrite the backend, database, financial logic, authentication or existing working AI integrations as part of this visual redesign.

Focus first on the consumer-facing mobile and responsive web experience.

## Stage 1 — Audit the current implementation

Inspect the actual source code and rendered application.

Identify:

* Existing page routes and navigation.

* Current component library and design tokens.

* Repeated generic card layouts.

* Typography and spacing inconsistencies.

* Poor photographic composition or low-quality imagery.

* Mobile responsiveness and viewport issues.

* Missing loading, animation and interaction states.

* Existing functionality that must remain intact.

Produce a concise visual gap report before editing.

## Stage 2 — Establish the GLAM AI design system

Create consistent tokens for:

* Premium typography.

* Warm ivory, blush, rose, mauve, champagne and charcoal colors.

* Responsive spacing and grid systems.

* Buttons, segmented controls, tabs and bottom sheets.

* Full-screen camera and portrait surfaces.

* Product cards and editorial collections.

* Hair and makeup selection carousels.

* Before/after comparisons.

* Skeleton loading and transformation progress.

* Accessibility and reduced-motion behavior.

Use real, appropriately licensed or approved visual assets. Do not fill finished screens with broken images, empty cards or repetitive generic stock photography.

## Stage 3 — Redesign five golden screens

Create and render these five screens before proceeding:

1. Personalized Home.

2. Face Analysis camera and report.

3. AI Studio makeover and hairstyle try-on.

4. Premium localized Shop.

5. Product Detail with virtual try-on and purchase actions.

Each screen must have mobile and desktop variants where appropriate.

Prioritize visual hierarchy, realistic user content, strong photographic composition, clear calls to action and smooth navigation.

## Stage 4 — Implement the signature interaction

The most important interaction is:

User uploads a selfie → receives analysis → selects a hairstyle or makeup look → sees a transformation preview → compares before and after → selects Get This Look → receives eligible product and professional recommendations → can buy or book.

Preserve the user's appearance and identity in previews unless the user explicitly requests a specific permitted modification.

Distinguish actual AI transformations from placeholders and mockups.

Organic recommendations must remain independent from advertiser influence. Clearly label sponsored listings.

## Stage 5 — Visual verification

Use automated browser screenshots and visual regression tests.

Test at minimum:

* iPhone-sized mobile viewport.

* Android-sized mobile viewport.

* Tablet viewport.

* Desktop viewport.

Compare each implemented screen against the approved visual specification.

Check layout, cropping, typography, spacing, colors, touch targets, navigation, modal behavior, loading states and responsiveness.

Do not declare completion based only on passing unit tests or successful compilation.

## Stage 6 — Approval gate

Submit the five golden screens for visual approval before redesigning the remaining screens.

Do not expand scope or replace working backend logic without approval.

Maintain the approved product functionality, including AI analysis, styling, merchant listings, location-aware discovery, advertisements, checkout and the 10% marketplace commission.

## Success criterion

GLAM AI must feel like a premium, immersive, mobile-first AI beauty platform with a connected commerce experience—not a generic SaaS dashboard, landing page or catalog template.

## 7. The most important decision

I would not ask Codex to redesign the entire application in one pass.

I would first demand one exceptional, fully interactive AI Studio makeover screen.

Why that screen? Because it forces the team to solve the hardest and most important design problems: portrait presentation, camera controls, transformations, hairstyle selection, makeup swatches, before/after comparisons and product recommendations.

Once that interaction looks and feels premium, it can establish the design standard for the rest of GLAM AI.

One question: Is Codex currently building GLAM AI directly in a React/Next.js web application, or is there already a separate React Native/Expo mobile application? That determines whether we should redesign the existing web interface first or establish the native mobile design system as the primary source of truth.
