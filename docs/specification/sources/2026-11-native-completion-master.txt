# 3. COMPLETE THE NATIVE PHOTO AND ANALYSIS FLOW

This is the first implementation priority.

Codex has identified a specific defect:

An asynchronous camera/photo picker may return after consent is withdrawn or the user navigates away.

Fix this with a robust lifecycle and session-fencing implementation.

Required protections:

- Capture the current authenticated user.
- Capture the current consent epoch.
- Capture the active screen/request generation.
- Invalidate outstanding operations when consent changes.
- Invalidate outstanding operations on logout/account switch.
- Prevent stale picker results from being uploaded.
- Prevent stale responses from updating UI.
- Prevent duplicate uploads.
- Clean up temporary sensitive media appropriately.
- Ensure deletion remains available after consent withdrawal.

Do not rely only on a component-mounted flag.

Then connect the full native workflow:

1. User opens Analyze.
2. User grants required consent.
3. User opens the native camera or photo library.
4. User selects or captures a photo.
5. App validates the selected image.
6. Photo uploads through the authenticated private-media API.
7. Upload progress is displayed.
8. Backend creates a persistent analysis job.
9. App displays actual job progress.
10. Results are retrieved from the backend.
11. User reviews results and confidence/uncertainty.
12. User corrects supported findings.
13. Corrected results are saved.
14. Style Passport is updated.
15. Results are accessible across sessions and devices.
16. User can delete applicable photos and results.

Preserve all F1A private-media protections.

If F1B analysis persistence is incomplete, implement the missing backend work through the approved migration process.

Do not fabricate results while the AI provider is unconfigured.
