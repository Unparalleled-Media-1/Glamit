# Visual gap report — before implementation

5 November 2026, Africa/Johannesburg. Source, current rendered Studio/Home captures and original image assets were inspected before application edits. This records the Stage 1 audit required by [Mandatory Visual Quality Recovery](sources/2026-11-mandatory-visual-quality-recovery.txt). The user's newest [Feature Freeze](sources/2026-11-final-feature-freeze.txt) stops additional major modules; [Destination Stylist](sources/2026-11-destination-stylist-directive.txt) is specified, not activated.

| Finding | Evidence and implication | Bounded correction |
|---|---|---|
| Two real clients already exist | Next.js consumer/business web and a separate Expo/React Native app share pure product state and canonical APIs | Design common patterns for both; responsive web captures are not native-device evidence |
| Route architecture | Home, Analyze, Studio, Advisor, Profile plus report/color/guide, event/builder/wardrobe/complete and business/admin routes exist | Preserve current primary tabs. The uploaded Home/Analyze/Studio/Shop/Profile change is explicitly a proposal, not approval to replace Advisor |
| Studio controls overpromise | A Comparison slider moves although no generated result exists; intensity is request metadata, not a live effect | Lock comparison without qualified output, explain intensity, add real reversible selection history and original preservation |
| Immersion is incomplete | Portrait/thumbnails/swatches exist, but the persistent Get This Look control is outside the editor and repeated full-size manual matching forms dominate the lower page | Put connected journey actions in the Studio action area; clearly separate optional request preparation from real offers |
| Commerce has no golden layouts | Get This Look is a component/no-match plan. Distinct Shop and Product Detail visual studies are absent | Add explicit editorial product studies with strong imagery and real controls, clearly not live inventory; keep purchase/try-on unavailable without qualification |
| Typography/spacing drift | Large global CSS with repeated late overrides, plus separately copied native styles, creates inconsistent hierarchy | Establish named shared tokens and one bounded golden-screen stylesheet; do not rewrite unrelated surfaces |
| Photography | The portrait sheet is original and usable. Repeated faces and generic material swatches cannot stand in for personal transformations. Existing product imagery is a mixed fashion/beauty contact sheet | Use original imagery with honest editorial labels; create dedicated unbranded beauty-product assets for Shop/Product Detail |
| Mobile control density | Fixed nav/safe-area geometry checks pass, but Studio options extend past the first view and need deliberate scrolling | Prioritize portrait and primary actions, bounded carousels, touch targets and clear advanced controls; test at phone/tablet/desktop sizes |
| State coverage | Local loading/file errors, offline guards, uncomputed reports and denied business workspaces exist; no model job or provider result is connected | Do not animate pretend scans/generation or invent success. Define actual provider loading/error/cancel/uncertainty states as integration gates |
| Functional boundaries | Consent/photo checks, immutable look-component editing, optional profile metadata, catalog/RBAC and 10% item policy already work within documented limits | Preserve them; no backend, database, auth, ledger, checkout or provider rewrite in this visual recovery |

Five approval studies: personalized Home; Face Analysis entry and uncomputed report; Studio; localized editorial Shop; Product Detail. Capture phone, Android-sized phone, tablet and desktop. Submit these patterns before redesigning other screens. There is no claim that disconnected inference, personal before/after, product matching, weather, merchant orders or payment integrations are working.
