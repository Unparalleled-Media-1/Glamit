## Reproducible SQL

`db/migrations/releases/0010_application.sql` is generated by executing the canonical application path on a new empty LOCAL build database and capturing its DDL/version records. The checksummed manifest binds the release to exact canonical source files. It includes existing application prerequisites and excludes sandbox 0009. The result is 38 public tables including the requested ten and existing supporting tables, not ten isolated tables that would break the existing API.

The exact SQL replays on a second fresh local database before deployment. An initial export omitted a comment-prefixed migration; the independent replay caught it before remote execution. Capture was corrected and the fresh replay passed. No failed SQL export was sent to Supabase.

```sh
# Source must be reviewed and the build database must be new, local and empty.
GLAM_MIGRATION_BUILD_DATABASE_URL=<secure-local-disposable-url> \
  uv run --frozen python scripts/export_application_migration.py

# Explicit apply refuses production, wrong parents, nonempty schemas/users/objects,
# changed release hashes or canonical-source drift. No automatic retries.
uv run --frozen python scripts/deploy_application_foundation.py \
  --project-ref vmzfiahjdfcuyzlyvewz --apply --report /tmp/foundation-result.json

# Verification alone never reapplies SQL.
uv run --frozen python scripts/deploy_application_foundation.py \
  --project-ref vmzfiahjdfcuyzlyvewz --report /tmp/foundation-verification.json
```
