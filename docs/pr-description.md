# Build the analysis-first consumer app and canonical workspace foundation

The application clients were development shells, while the design prototype emphasized shopping. This change implements the corrected Home / Analyze / AI Studio / AI Advisor / Profile experience in Expo and Next.js, with consent-first device-only photo preparation, dedicated report/color/guide/Studio/history/privacy screens, editable session routines, optional interests and secondary commerce/companion interfaces. The editorial visual identity is retained. AI reports stay uncomputed and originals stay unchanged until qualified providers are connected.

A unified business portal supplies five role inventories, task-specific planning forms and isolated session notes; `/admin` exposes only a denied public inventory. The canonical backend adds owner-only routine CRUD, scoped business draft CRUD, multi-role organization capability checks, recipient-bound invitations, revocation and a separate staff-context boundary requiring fresh privileged assurance. Additive migrations through `0006_staff_context` enable deny-by-default client RLS. Typed API contracts and an in-memory-auth client port accompany real PostgreSQL isolation, conflict, idempotency, invitation and staff tests.

Validation: 63 backend tests passed on the dedicated local PostgreSQL test database; three shared client/API-port tests passed; actual Next.js Chromium checks cover six journey/security/responsive groups. Lint/format, TypeScript, web build, shared React runtime checks and both Expo JS exports passed. Production npm audit reported zero vulnerabilities. Current evidence and limits are in validation.md and docs/application-preview.

External identity, hosted database, private storage, analysis/makeover/Advisor providers, catalogs, payments and verified business operations remain deferred. The UI planning forms do not constitute fully implemented marketplace, advertising, booking, publication or admin execution. Native camera/device testing and complete localization/accessibility/provider-quality/pilot qualification remain open. No paid provider calls, production migration/deployment, Git push, merge, PR publication or cloud-environment publication was performed. Application implementation is authorized by the user's latest explicit instruction; old design-wait wording is superseded for this build.
